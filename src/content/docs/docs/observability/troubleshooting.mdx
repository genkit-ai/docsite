The following sections detail solutions to common issues that developers run
into when using Genkit Monitoring.

## I can't see traces or metrics in Genkit Monitoring

1.  Ensure that the following APIs are enabled for your underlying Google Cloud project:
    - [Cloud Logging API](https://console.cloud.google.com/apis/library/logging.googleapis.com)
    - [Cloud Trace API](https://console.cloud.google.com/apis/library/cloudtrace.googleapis.com)
    - [Cloud Monitoring API](https://console.cloud.google.com/apis/library/monitoring.googleapis.com)
2.  Ensure that the following roles are applied to the service account that is running your code (or service account that has been configured as part of the plugin options) in [Cloud IAM](https://console.cloud.google.com/iam-admin/iam).
    - **Monitoring Metric Writer** (`roles/monitoring.metricWriter`)
    - **Cloud Trace Agent** (`roles/cloudtrace.agent`)
    - **Logs Writer** (`roles/logging.logWriter`)
3.  Inspect the application logs for errors writing to Cloud Logging, Cloud Trace, and Cloud Monitoring. On Google Cloud infrastructure such as Firebase Functions and Cloud Run, even when telemetry is misconfigured, logs to `stdout/stderr` are automatically ingested by the Cloud Logging Agent, allowing you to diagnose issues in the in the [Cloud Logging Console](https://console.cloud.google.com/logs).

<Lang lang="go">

If your application calls `tracing.SetInstrumentation`, make sure the providers
it lists include `&tracing.OTelInstrumentation{}`. The plugin builds its traces,
metrics, and logs from the OpenTelemetry spans and `genkit:*` attributes that
this default provider writes, so a list without it stops the Genkit metrics.
That includes the
[OpenTelemetry GenAI instrumentation](/docs/observability/otel-genai-semantic-conventions)
on its own, which is not for use together with the Firebase plugin.

</Lang>

<Lang lang="js">

If your application calls `configureInstrumentation` from `genkit/tracing`, it
has replaced the default OpenTelemetry provider. The plugin builds its metrics
and logs from the `genkit:*` attributes that the default provider writes, so the
Genkit metrics stop without an error. That includes the
[OpenTelemetry GenAI instrumentation](/docs/observability/otel-genai-semantic-conventions)
from `@genkit-ai/otel`, which is not for use together with the Firebase plugin.

</Lang>

<Lang lang="python">

Also check the following:

- **`GENKIT_ENV=dev`**: `genkit start` sets it, and nothing is exported unless
  you pass `force_dev_export=True`.
- **Wrong project**: `FIREBASE_PROJECT_ID` is not read. Set `project=` or
  `GOOGLE_CLOUD_PROJECT`; see
  [project resolution](/docs/observability/getting-started#environment-based-configuration).
- **No metrics, and `Error exporting metrics to GCP` at startup with
  `'GenkitMetricExporter' object has no attribute '_preferred_aggregation'`**:
  a known issue in `genkit-google-cloud` 0.13. The Cloud Monitoring exporter
  fails to start, so no metrics are sent. Traces and logs still export.
- **Your own `TracerProvider` gets no spans**: register it before calling
  `enable_google_cloud_telemetry()`. OpenTelemetry ignores a provider set after
  one is already registered and logs
  `Overriding of current TracerProvider is not allowed`.
- **GenAI spans appear twice**: `configure_instrumentation(GenAiInstrumentation(...))`
  after `enable_google_cloud_telemetry()` adds a second instance. Configure yours
  first; `enable_google_cloud_telemetry()` keeps it instead of adding its own.
- **`FAILED_PRECONDITION` on startup**: `enable_google_cloud_telemetry()` runs
  once per process. A second call raises instead of adding a second set of
  exporters.
- **Error messages show `<redacted>` in Cloud Trace**: on Genkit spans, the
  status description, `exception.message`, and `exception.stacktrace` are
  redacted because `str(exc)` can quote prompt text. `error.type` and
  `exception.type` are kept. Log the exception with `genkit.get_logger()` if you
  need the message.

</Lang>

Debug locally:

<Lang lang="js">

Enable dev export:

```typescript
enableFirebaseTelemetry({
  forceDevExport: true,
});
```

</Lang>

<Lang lang="go">

Enable dev export:

```go
firebase.EnableFirebaseTelemetry(&firebase.FirebaseTelemetryOptions{
	ForceDevExport: true,
})
```

</Lang>

<Lang lang="python">

Enable dev export. Under `genkit start`, metrics already export every 5
seconds; `metric_export_interval_ms=5000` gives the same interval when you run
the app without it:

```python
from genkit_google_cloud import enable_google_cloud_telemetry

enable_google_cloud_telemetry(
    force_dev_export=True,
    metric_export_interval_ms=5000,
)
```

</Lang>

To test with your personal user credentials, use the
[gcloud CLI](https://cloud.google.com/sdk/docs/install) to authenticate with
Google Cloud. Doing so can help diagnose enabled or disabled APIs, but does
not test the gcloud auth application-default login.

Alternatively, impersonating the service account lets you test
production-like access. You must have the
`roles/iam. serviceAccountTokenCreator` IAM role applied to your user account
in order to impersonate service accounts:

```bash
gcloud auth application-default login --impersonate-service-account <SERVICE_ACCT_EMAIL>
```

See the
[ADC](https://cloud.google.com/js/authentication/set-up-adc-local-dev-environment)
documentation for more information.

## Request count does not match traces count

At low volumes (\<1 query per second), you may notice that your metric counts,
like requests or failed paths, do not match the number of traces shown in the
traces table. Below are three common reasons for this happening.

### Metric and trace export intervals can be different

In some cases, the dashboard shows traces that have exported but metrics that
have not, or vice versa.

You can reduce the likelihood of this happening by adjusting the metric export
interval to be more frequent. By default, metrics are exported every 5 minutes.
The minimum allowable export interval is 5 seconds.

:::note
Exporting metrics more frequently can result in increased costs.
:::

<Lang lang="js">

```typescript
enableFirebaseTelemetry({
  // Override the export interval to 3 minutes
  metricExportIntervalMillis: 180_000,
  // Override the export timeout to 3 minutes
  metricExportTimeoutMillis: 180_000,
});
```

</Lang>

<Lang lang="go">

```go
import "github.com/firebase/genkit/go/plugins/firebase"

func main() {
	interval := 180000
	firebase.EnableFirebaseTelemetry(&firebase.FirebaseTelemetryOptions{
		// Override the export interval to 3 minutes
		MetricExportIntervalMillis: &interval,
		// Override the export timeout to 3 minutes
		MetricExportTimeoutMillis:  &interval,
	})
}
```

</Lang>

<Lang lang="python">

```python
from genkit_google_cloud import enable_google_cloud_telemetry

enable_google_cloud_telemetry(
    # Override the export interval to 3 minutes
    metric_export_interval_ms=180_000,
    # Override the export timeout to 3 minutes
    metric_export_timeout_ms=180_000,
)
```

</Lang>

### Intermittent network issues

<Lang lang="js">

Occasionally you may have transient network issues that result in a failure to
upload telemetry data. These failures are logged to Google Cloud Logging. To
see the specific failure reason, look for a log that starts with:

> Unable to send telemetry to Google Cloud: Error: Send TimeSeries failed:

</Lang>

<Lang lang="go">

Occasionally you may have transient network issues that result in a failure to
upload telemetry data. These failures are logged to Google Cloud Logging. To
see the specific failure reason, look for a log that contains:

> level=ERROR msg="Unable to send metrics to Google Cloud" error="rpc error: code = PermissionDenied desc = Permission monitoring.metricDescriptors.create denied (or the resource may not exist).

</Lang>

<Lang lang="python">

Occasionally you may have transient network issues that result in a failure to
upload telemetry data. These failures are written to the application log through
`genkit.get_logger()`. Look for:

- **Permission errors**: `Unable to send traces to Google Cloud.`,
  `Unable to send metrics to Google Cloud.`, or
  `Unable to send logs to Google Cloud.`. The first one per signal names the
  IAM role to grant.
- **Other failures**: `Error exporting traces to GCP`,
  `Error exporting metrics to GCP`, or `Error exporting logs to GCP`, with the
  underlying error in the `error` field.

</Lang>

### Telemetry upload reliability in Firebase Functions or Cloud Run

When your Genkit code is hosted in Google Cloud Run or Cloud Functions for
Firebase, telemetry-data upload may be less reliable as the container switches
to the "idle"
[lifecycle state](https://cloud.google.com/blog/topics/developers-practitioners/lifecycle-container-cloud-run).
If higher reliability is important to you, consider changing
[CPU allocation](https://cloud.google.com/run/docs/configuring/cpu-allocation)
to **Instance-based billing** (previously called **CPU always allocated**) in the Google Cloud Console.

:::note
The **Instance-based billing** setting impacts pricing. Check [Cloud Run pricing](https://cloud.google.com/run/pricing) before enabling this setting.
:::

To switch to instance-based billing, run

```bash
gcloud run services update YOUR-SERVICE --no-cpu-throttling
```
