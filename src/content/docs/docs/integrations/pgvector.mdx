[pgvector](https://github.com/pgvector/pgvector) is a PostgreSQL extension that
adds vector similarity search. It lets you keep embeddings next to the
relational data they describe and query both in one statement.

There is no Genkit plugin for pgvector, and you don't need one. This page shows
two flows that talk to the database directly: one that indexes text and one that
retrieves documents for a query. Use them as a starting point and adapt the SQL
to your own schema. See [Retrieval-augmented generation](/docs/rag) for how
these pieces fit together.

The examples index recaps of TV episodes and answer questions about a show.

## Create the table

```sql
-- Enable the pgvector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- One row per chunk of recap text
CREATE TABLE embeddings (
  id            SERIAL PRIMARY KEY,
  show_id       TEXT NOT NULL,
  season_number INT  NOT NULL,
  episode_id    INT  NOT NULL,
  chunk         TEXT NOT NULL,
  embedding     vector(768) NOT NULL
);

-- Index for efficient vector similarity search
CREATE INDEX ON embeddings USING hnsw (embedding vector_cosine_ops);
```

Two constraints tie this DDL to the code below:

- The width in `vector(N)` must equal the number of dimensions your embedder
  emits. `gemini-embedding-001` emits 3072 by default, which is above the
  2000-dimension ceiling on pgvector's `ivfflat` and `hnsw` indexes, so the code
  asks for 768.
- The index operator class must match the distance operator your query uses:
  `vector_cosine_ops` with `<=>`, `vector_l2_ops` with `<->`, `vector_ip_ops`
  with `<#>`. A query that uses a different operator ignores the index and
  falls back to a sequential scan.

## Setup

Install the PostgreSQL client and the pgvector helpers:

```bash
npm install postgres pgvector
```

Configure Genkit, the database connection, and the embedder:

```ts
import { googleAI } from '@genkit-ai/google-genai';
import { Document, DocumentDataSchema, genkit, z } from 'genkit';
import pgvector from 'pgvector';
import postgres from 'postgres';

const ai = genkit({
  plugins: [googleAI()],
  model: googleAI.model('gemini-flash-latest'),
});

// postgres() returns a pooled client; create one per process and share it.
const sql = postgres('postgres://user:password@localhost:5432/recaps');

const embedder = googleAI.embedder('gemini-embedding-001');
const EMBEDDING_DIMENSIONS = 768; // must match vector(768) in the table
```

## Index documents

The indexing flow embeds a batch of chunks and inserts one row per chunk. Gemini
embedders produce better retrieval results when you tell them which side of the
search a text is on, so it uses the `RETRIEVAL_DOCUMENT` task type.

```ts
export const indexRecap = ai.defineFlow(
  {
    name: 'indexRecap',
    inputSchema: z.object({
      show: z.string(),
      season: z.number().int(),
      episode: z.number().int(),
      chunks: z.array(z.string()),
    }),
    outputSchema: z.object({ rowsInserted: z.number() }),
  },
  async ({ show, season, episode, chunks }) => {
    if (chunks.length === 0) {
      return { rowsInserted: 0 };
    }
    const embeddings = await ai.embedMany({
      embedder,
      content: chunks,
      options: { outputDimensionality: EMBEDDING_DIMENSIONS, taskType: 'RETRIEVAL_DOCUMENT' },
    });
    const rows = chunks.map((chunk, i) => ({
      show_id: show,
      season_number: season,
      episode_id: episode,
      chunk,
      embedding: pgvector.toSql(embeddings[i].embedding),
    }));
    await sql`INSERT INTO embeddings ${sql(rows)}`;
    return { rowsInserted: rows.length };
  }
);
```

## Retrieve documents

The retrieval flow embeds the query with the `RETRIEVAL_QUERY` task type and
runs a nearest-neighbor search scoped to one show. It returns Genkit documents,
with the other columns and the distance in each document's metadata.

```ts
export const RecapQuerySchema = z.object({
  query: z.string(),
  show: z.string(),
  k: z.number().int().positive().optional().describe('Number of results, default 3'),
});

export const retrieveRecaps = ai.defineFlow(
  {
    name: 'retrieveRecaps',
    inputSchema: RecapQuerySchema,
    outputSchema: z.array(DocumentDataSchema),
  },
  async ({ query, show, k = 3 }) => {
    const [{ embedding }] = await ai.embed({
      embedder,
      content: query,
      options: { outputDimensionality: EMBEDDING_DIMENSIONS, taskType: 'RETRIEVAL_QUERY' },
    });
    // <=> is cosine distance, matching the vector_cosine_ops index.
    const rows = await sql<
      { episode_id: number; season_number: number; content: string; distance: number }[]
    >`
      SELECT episode_id, season_number, chunk AS content,
             embedding <=> ${pgvector.toSql(embedding)} AS distance
      FROM embeddings
      WHERE show_id = ${show}
      ORDER BY distance
      LIMIT ${k}`;
    return rows.map(({ content, ...metadata }) => Document.fromText(content, metadata));
  }
);
```

Because the flow owns the SQL, adding filters (a season range, a minimum
similarity, a tenant ID from the [auth context](/docs/deployment/authorization))
is a change to the `WHERE` clause and the input schema.

## Use the documents in a RAG flow

Call the retrieval flow like a function and pass its output to `generate`:

```ts
export const askAboutShow = ai.defineFlow(
  {
    name: 'askAboutShow',
    inputSchema: z.object({ question: z.string(), show: z.string() }),
    outputSchema: z.string(),
  },
  async ({ question, show }) => {
    const docs = await retrieveRecaps({ query: question, show });
    const { text } = await ai.generate({
      system: 'Answer using only the episode recaps provided. Say so if they do not cover the question.',
      prompt: question,
      docs,
    });
    return text;
  }
);
```

To let the model decide when and what to search instead, expose the same flow as
a tool:

```ts
export const searchRecaps = ai.defineTool(
  {
    name: 'searchRecaps',
    description: 'Searches episode recaps for a show. Returns the most relevant passages.',
    inputSchema: RecapQuerySchema,
    outputSchema: z.array(DocumentDataSchema),
  },
  (input) => retrieveRecaps(input)
);
```

## Setup

Install the PostgreSQL driver and the pgvector helpers:

```bash
go get github.com/lib/pq
go get github.com/pgvector/pgvector-go
```

The examples on this page use these imports:

```go
import (
	"cmp"
	"context"
	"database/sql"
	"log"

	"github.com/firebase/genkit/go/ai"
	"github.com/firebase/genkit/go/genkit"
	"github.com/firebase/genkit/go/plugins/googlegenai"
	_ "github.com/lib/pq"
	pgv "github.com/pgvector/pgvector-go"
	"google.golang.org/genai"
)
```

`_ "github.com/lib/pq"` is a blank import. Nothing in your code refers to the
package; importing it for its side effects is what registers the `postgres`
driver name that `sql.Open` looks up.

### Connect to the database

`*sql.DB` is already a connection pool, so open one per process and share it.

```go
db, err := sql.Open("postgres", "postgres://user:password@localhost:5432/recaps?sslmode=disable")
if err != nil {
	log.Fatal(err)
}
defer db.Close()
```

### Choose an embedder

Indexing and querying must produce vectors of the same width, but Gemini
embedders want a different task type for each side:

```go
const embedDim = 768 // must match vector(768) in the table

docEmbedder := googlegenai.EmbedderRef("googleai/gemini-embedding-001", &genai.EmbedContentConfig{
	TaskType:             "RETRIEVAL_DOCUMENT",
	OutputDimensionality: genai.Ptr[int32](embedDim),
})

queryEmbedder := googlegenai.EmbedderRef("googleai/gemini-embedding-001", &genai.EmbedContentConfig{
	TaskType:             "RETRIEVAL_QUERY",
	OutputDimensionality: genai.Ptr[int32](embedDim),
})
```

## Index documents

The indexing flow embeds a batch of chunks and inserts one row per chunk in a
single transaction:

```go
type RecapChunks struct {
	Show    string   `json:"show"`
	Season  int      `json:"season"`
	Episode int      `json:"episode"`
	Chunks  []string `json:"chunks"`
}

genkit.DefineFlow(g, "indexRecap", func(ctx context.Context, in RecapChunks) (int, error) {
	if len(in.Chunks) == 0 {
		return 0, nil
	}
	res, err := genkit.Embed(ctx, g, ai.WithEmbedder(docEmbedder), ai.WithTextDocs(in.Chunks...))
	if err != nil {
		return 0, err
	}

	tx, err := db.BeginTx(ctx, nil)
	if err != nil {
		return 0, err
	}
	defer tx.Rollback() // no-op after Commit
	for i, chunk := range in.Chunks {
		if _, err := tx.ExecContext(ctx, `
			INSERT INTO embeddings (show_id, season_number, episode_id, chunk, embedding)
			VALUES ($1, $2, $3, $4, $5)`,
			in.Show, in.Season, in.Episode, chunk, pgv.NewVector(res.Embeddings[i].Embedding)); err != nil {
			return 0, err
		}
	}
	return len(in.Chunks), tx.Commit()
})
```

## Retrieve documents

The retrieval flow embeds the query, then runs a nearest-neighbor search scoped
to one show. It returns Genkit documents, with the other columns and the
distance in each document's metadata.

```go
type RecapQuery struct {
	Query string `json:"query"`
	Show  string `json:"show"`
	K     int    `json:"k,omitempty"` // number of results; 0 means 3
}

retrieveRecaps := genkit.DefineFlow(g, "retrieveRecaps",
	func(ctx context.Context, in RecapQuery) ([]*ai.Document, error) {
		res, err := genkit.Embed(ctx, g, ai.WithEmbedder(queryEmbedder), ai.WithTextDocs(in.Query))
		if err != nil {
			return nil, err
		}

		// <=> is cosine distance, matching the vector_cosine_ops index.
		rows, err := db.QueryContext(ctx, `
			SELECT episode_id, season_number, chunk, embedding <=> $2 AS distance
			FROM embeddings
			WHERE show_id = $1
			ORDER BY distance
			LIMIT $3`,
			in.Show, pgv.NewVector(res.Embeddings[0].Embedding), cmp.Or(in.K, 3))
		if err != nil {
			return nil, err
		}
		defer rows.Close()

		var docs []*ai.Document
		for rows.Next() {
			var episode, season int
			var chunk string
			var distance float64
			if err := rows.Scan(&episode, &season, &chunk, &distance); err != nil {
				return nil, err
			}
			docs = append(docs, ai.DocumentFromText(chunk, map[string]any{
				"episode_id":    episode,
				"season_number": season,
				"distance":      distance,
			}))
		}
		return docs, rows.Err()
	})
```

Because the flow owns the SQL, adding filters (a season range, a minimum
similarity, a tenant ID from the [auth context](/docs/deployment/authorization))
is a change to the `WHERE` clause and the input struct.

## Use the documents in a RAG flow

Run the retrieval flow and pass its output to `Generate`:

```go
type AskInput struct {
	Question string `json:"question"`
	Show     string `json:"show"`
}

genkit.DefineFlow(g, "askAboutShow", func(ctx context.Context, in AskInput) (string, error) {
	docs, err := retrieveRecaps.Run(ctx, RecapQuery{Query: in.Question, Show: in.Show})
	if err != nil {
		return "", err
	}
	return genkit.GenerateText(ctx, g,
		ai.WithSystem("Answer using only the episode recaps provided. Say so if they do not cover the question."),
		ai.WithPrompt(in.Question),
		ai.WithDocs(docs...))
})
```

To let the model decide when and what to search instead, expose the same flow as
a tool:

```go
searchRecaps := genkit.DefineTool(g, "searchRecaps",
	"Searches episode recaps for a show. Returns the most relevant passages.",
	func(ctx *ai.ToolContext, in RecapQuery) ([]*ai.Document, error) {
		return retrieveRecaps.Run(ctx, in)
	})
```
